# Cut Application tracking and Cover Letter from v1.0 — resume tailoring only

**Supersedes:** [0002](./0002-lazy-persistence-until-application-confirmed.md) (its persistence trigger no longer applies).

v1.0 previously included a CRM-style Application tracking pipeline (Applied → Screening → Technical Interview(s) → Offer → Negotiation → outcome, with a Company entity and fields like salary range and follow-up dates) and a Tailored Cover Letter artifact alongside the Tailored Resume. We cut both to keep v1.0 as lean and fast to ship as possible: the core value is getting a grounded, tailored resume for a specific job, and both cut pieces are separable, well-defined-enough-to-build-later features rather than prerequisites for that value. Cover Letter in particular was judged to need its own dedicated conversational flow (grounding a "why this company" section well is a real design problem, not a small addition) and isn't needed for a lean v1.0.

Consequence: with no Application to key off of, [ADR-0002](./0002-lazy-persistence-until-application-confirmed.md)'s persistence trigger ("persist once an Application is confirmed") no longer has anything to trigger on, and `Company` has no reason to exist as a persisted entity in v1.0 (it only ever served Application's tracking fields). What *does* persist once a Candidate confirms intent to tailor — and whether Company facts get looked up fresh vs. stored at all — is deliberately left open here; it gets resolved during the Job Matching/Tailoring scoping and prototyping pass, not decided speculatively in this ADR.
